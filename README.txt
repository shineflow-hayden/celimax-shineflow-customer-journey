Celimax US 액션아이템 공동 저장 설정
연결 정보 수정일: 2026-10-05

날짜 입력 수정본 적용
이미 Supabase 설정을 마쳤다면 GitHub의 index.html을 이번 파일로 교체해 다시 배포하면 됩니다. 설정 SQL은 다시 실행할 필요가 없습니다.
날짜 입력을 개선해 숫자 8자리가 완성되면 자동 저장하고, 변경 이벤트만 전달되는 입력도 처리하도록 수정했습니다.

이번 파일에 반영한 내용
- 전달해 주신 Project URL과 Publishable key를 HTML에 반영했습니다.
- 담당자, 반영 예정일, 완료 여부, 반영 후 결과를 Supabase에 저장합니다.
- 웹페이지의 로그인 기능은 추가하지 않았습니다.
- 액션아이템 페이지를 열어 둔 동안 약 5초마다 다른 사용자의 변경 내용을 불러옵니다. 브라우저 탭으로 돌아올 때도 갱신합니다.
- 제품별 개선안, 디자인 링크와 키워드 자료는 기존 HTML에 그대로 남아 있습니다.

먼저 해야 하는 작업
새 프로젝트 URL과 Publishable key를 HTML에 반영했습니다. 실제 데이터 조회와 저장은 새 프로젝트의 테이블 및 접근 권한 설정 후 확인해야 합니다. 이번 변경에서는 서버 연결이나 저장을 테스트하지 않았습니다.
아래 1번 SQL 실행 후 2번 파일 교체를 하면 됩니다. SQL을 실행하기 전에는 입력란이 비활성화되고 설정 안내가 표시됩니다.

1. Supabase에서 저장 테이블 만들기
1) https://supabase.com/dashboard 에 로그인합니다.
   이 로그인은 관리자 설정용입니다. 완성된 웹페이지 방문자에게는 로그인을 요구하지 않습니다.
2) 프로젝트 주소가 https://mkuinihocmalpecjunbf.supabase.co 인 프로젝트를 선택합니다.
3) 왼쪽 SQL Editor에서 새 쿼리를 엽니다.
   바로가기: https://supabase.com/dashboard/project/mkuinihocmalpecjunbf/sql/new
4) 함께 전달한 Celimax_Supabase_설정.sql을 메모장이나 코드 편집기로 엽니다.
   ZIP 안에서는 supabase_setup.sql이라는 이름으로 들어 있습니다. 두 파일의 내용은 같습니다.
5) 파일 내용 전체를 복사해 SQL Editor에 붙여 넣은 뒤 Run을 누릅니다. postgres 역할로 실행합니다.
6) 마지막 결과의 action_item_count가 68인지 확인합니다.
7) Table Editor에서 public.celimax_action_items를 열면 제품명과 액션아이템, 입력값을 볼 수 있습니다.

SQL은 기존에 입력된 담당자, 날짜, 완료 여부와 결과를 지우지 않습니다. 같은 SQL을 다시 실행해도 기존 입력은 유지됩니다.
RLS를 수동으로 끄거나 전체 테이블에 권한을 추가할 필요가 없습니다. 제공한 SQL이 이 테이블의 조회와 네 가지 입력 항목 수정만 허용합니다.

2. GitHub와 Vercel에 새 파일 반영하기
1) Celimax_US_Vercel_GitHub_업로드용.zip의 압축을 풉니다.
2) 사용 중인 GitHub 저장소에서 index.html과 vercel.json을 새 파일로 교체하고 Commit changes를 누릅니다.
   저장소: https://github.com/shineflow-hayden/celimax-customer-journey
   README.txt와 supabase_setup.sql은 설정 참고 파일이므로 웹 배포에 꼭 올릴 필요는 없습니다.
3) 해당 저장소가 Vercel에 연결되어 있다면 새 배포가 완료될 때까지 기다립니다.
4) 아직 연결하지 않았다면 Vercel에서 GitHub 저장소를 Import하고 다음 설정으로 배포합니다.
   Framework Preset: Other
   Root Directory: index.html이 있는 폴더
   Build Command: 비워두기
   Install Command: 비워두기
   Output Directory: .
5) 이번 파일은 URL과 Publishable key가 코드에 들어 있으므로 환경변수를 추가하지 않아도 됩니다.
6) 배포 주소를 열어 액션아이템 트래커 상단에 '공동 저장 연결됨'이 표시되는지 확인합니다.

단독 HTML 파일도 인터넷에 연결된 상태라면 같은 Supabase 데이터를 사용합니다.

3. 공동 저장 확인하기
1) 일반 브라우저와 시크릿 창, 또는 서로 다른 두 기기에서 같은 배포 주소를 엽니다.
2) 두 창 모두 액션아이템 트래커 페이지를 선택합니다.
3) 한 창에서 담당자 이름을 입력합니다. 잠시 입력을 멈추거나 다른 칸을 클릭합니다.
4) 반영 예정일에 20261001처럼 숫자 8자리를 입력하고 Enter를 누르거나 다른 칸을 클릭합니다.
5) 완료를 체크하고 결과도 입력한 뒤 '공동 저장 완료'를 확인합니다.
6) 다른 창에 약 5초 안에 변경 내용이 표시되는지 확인합니다. 새로고침 후에도 유지되어야 합니다.
7) 테스트용으로 넣은 값은 다시 비우거나 실제 값으로 바꿉니다.

사용 방식
- 담당자와 결과는 입력을 잠시 멈추면 자동 저장됩니다. 한글 조합 중인 글자는 조합이 끝난 뒤 저장합니다.
- 날짜는 20261001처럼 유효한 숫자 8자리를 입력하면 자동 저장됩니다. Enter를 누르거나 입력칸을 벗어나면 화면에 '2026년 10월 1일' 형태로 표시됩니다.
- 2026-10-01, 2026/10/01 형식의 붙여넣기도 가능합니다. 날짜가 완성되지 않았거나 존재하지 않는 날짜이면 저장하지 않습니다.
- 완료 체크는 바로 저장 요청을 보냅니다.
- 서로 다른 칸을 수정하면 각자가 변경한 칸만 저장합니다. 같은 칸을 동시에 수정하면 서버가 마지막으로 저장한 값이 남습니다.
- 다른 사람이 수정한 내용은 입력 중인 칸의 커서를 건드리지 않고, 입력칸을 벗어난 뒤 표시합니다.
- '공동 저장 완료'가 나오기 전에는 페이지를 닫지 않는 편이 좋습니다.
- 저장 실패 시 '다시 저장'을 눌러 재시도할 수 있습니다. 이때까지 입력값은 해당 탭에 임시 보관됩니다. 같은 탭에서 새로고침하면 미저장 내용을 확인하고 다시 저장할 수 있습니다.
- 인터넷 연결이 끊겨 처음부터 데이터를 불러오지 못하면 입력란을 잠급니다. 연결 후 '다시 연결'을 누릅니다.
- CSV 다운로드는 현재 표시된 항목을 내보냅니다.
- '작성본 저장'은 현재 입력을 포함한 별도 HTML 백업을 만듭니다. 이 백업은 저장 시점의 내용을 유지하며, 백업 안에서 수정한 값은 Supabase에 보내지 않습니다.

기존 브라우저 입력값
이전 버전의 브라우저별 입력값은 공용 데이터에 자동으로 덮어쓰지 않습니다.
이전에 작성한 값이 있다면 이전 HTML의 CSV 또는 작성본을 보관하고, 새 공동 화면에 필요한 값을 옮겨 입력해 주세요.
기존 브라우저 저장값 자체를 삭제하지는 않습니다.

연결 문제가 있을 때
- 'Supabase 설정이 필요합니다': 프로젝트 선택과 SQL 전체 실행 여부를 확인합니다. Table Editor에 68개 항목이 있어야 합니다.
- 테이블이 있는데도 조회되지 않으면 프로젝트의 Data API가 켜져 있고 public 스키마가 노출되어 있는지 확인합니다.
- 'Supabase 키와 저장 권한을 확인': 전달한 키가 현재 프로젝트의 Publishable key인지 확인하고 설정 SQL을 다시 실행합니다.
- '저장되지 않은 내용이 있습니다': 네트워크 연결과 Supabase 프로젝트 상태를 확인한 뒤 '다시 저장'을 누릅니다. 해결 전에는 '작성본 저장'으로 입력 내용을 보관합니다.
- 옛날의 '이 브라우저에 자동 저장' 표시가 보이면 새 index.html이 배포되지 않았거나 예전 파일을 열고 있는 것입니다.

로그인 없는 운영 범위
이 버전은 웹페이지나 공개키를 가진 사람이 액션아이템을 조회하고 수정할 수 있습니다. 담당자 이름은 직접 입력한 값이며, 수정자의 신원을 인증하는 기록은 아닙니다.
제품명과 액션아이템 제목의 수정, 항목 추가와 삭제는 방문자에게 허용하지 않습니다.
Secret key나 service_role 키는 필요하지 않습니다. HTML이나 GitHub에 넣지 마세요.
이후 팀원과 고객사별 접근 제한이 필요해지면 로그인과 사용자별 권한을 별도로 연결하면 됩니다.

구현 참고
- 저장 테이블: public.celimax_action_items
- 수정 가능한 열: assignee, planned_date, is_done, result
- 수정 순서 확인용 열: revision, updated_at
- 통신: Supabase REST API, GET 조회와 PATCH 수정
- 동기화: 화면이 열린 동안 5초 간격 조회. Realtime 설정은 필요하지 않습니다.
- 외부 JavaScript 라이브러리, 별도 서버, 별도 빌드 과정은 필요하지 않습니다.
